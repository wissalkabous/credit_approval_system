Présentation du modèle et du pipeline ML

Algorithme : Random Forest Dataset : 1 000 clients Features : 12 Marché : Maroc (MAD)
01 — Problème

Classification Binaire

Le modèle répond à une seule question :

Ce client va-t-il rembourser son crédit ?
1 — APPROVED
0 — REJECTED

C'est un problème de classification supervisée : on dispose de données historiques avec la réponse connue (Approval), et on entraîne un modèle à apprendre le pattern pour prédire de nouveaux clients.

03 — Pipeline de Données

DataProcessor — 4 étapes

load()
pd.read_csv() — Charger le fichier CSV en DataFrame pandas. Vérification de la forme et des types.
clean()
Suppression doublons · fillna(mean) pour les colonnes numériques · fillna(mode) pour les colonnes catégorielles.
encode()
LabelEncoder sur les colonnes object — ici toutes les features sont déjà numériques, donc étape transparente mais prête pour l'extension.
prepare()
Séparation X / y (features / target) → train_test_split (80 % / 20 %, stratify=y) → StandardScaler.fit_transform(X_train) puis .transform(X_test)
Pourquoi stratify=y ? Pour garantir que le split garde la même proportion approved/rejected dans le train ET le test (65%/35%). Sans ça, les métriques seraient faussées si le test avait par hasard trop d'un seul label.
Pourquoi StandardScaler ? Random Forest n'en a pas besoin (basé sur des seuils, pas des distances). On le garde pour que le même pipeline fonctionne si on change d'algorithme (Logistic Regression, SVM…) sans modifier le code.

# 100 arbres de décision — chacun vote

            100 Arbres de Décision
         /         |           \
    Arbre 1     Arbre 2    ...  Arbre 100
  (63% data) (63% data) (63% data)
      |            |               |
   Vote=1      Vote=0          Vote=1
       \           |          /
          VOTE MAJORITAIRE
             → APPROVED

Chaque arbre est entraîné sur un sous-échantillon aléatoire des données et des features. Ils font des erreurs différentes, donc ensemble ils sont bien plus robustes qu'un seul arbre (technique : Bagging).

from sklearn.ensemble import RandomForestClassifier

model = RandomForestClassifier(
    n_estimators=100,    # 100 arbres de décision
    max_depth=10,        # profondeur max → évite l'overfitting
    random_state=42,    # reproductibilité garantie
    n_jobs=-1           # parallélisme : utilise tous les CPUs
)

Point critique — Le StandardScaler : Le scaler est fitté une seule fois sur X_train pendant le training, puis sérialisé avec le modèle. À chaque prédiction, on appelle uniquement .transform(). Si on le re-fittait sur les nouvelles données, les valeurs normalisées changeraient et le modèle donnerait des résultats faux.
